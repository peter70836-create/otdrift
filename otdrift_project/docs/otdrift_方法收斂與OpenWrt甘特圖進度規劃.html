🎯 一、 指導教授「方法要收斂」的核心本質剖析

教授在指導會議指出「方法要收斂 (Methodological Convergence)」，其深層含意在於：切忌包山包海、堆疊工具，必須收斂成一條清晰、嚴密、不可替代的學術技術主線：

收斂維度 方法發散 (收斂前) 聚焦收斂 (收斂後) 學術價值與競爭優勢
1. 部署載體定位 跑在一般電腦/Ubuntu 的分析軟體 Purdue 1.5 層 OpenWrt 邊緣安全閘道器 符合工控現場實體分層，具備真實軟硬整合落地性。
2. 工控通訊載體 抽象提及多種 OT 協定 鎖定 Modbus TCP (Port 502) / RTU 全球最通用工控骨幹，文獻與測試台最容易被審查人信服。
3. 差分比對演算法 單純調用第三方 DeepDiff 輸出字串 加權樹編輯距離 (W-STED) + 不變量約束 提供嚴謹數學形式化定義與歸一化飄移指數 ($NDI \in [0, 1]$)。
4. 實驗評測基準 實驗室 4 筆手工造假 Toy Example SUTD SWaT 權威基準 (100 樣本全矩陣) 國際公認測試集，數據具備權威性與高說服力。

💡 二、 目前整體架構的三大改進空間與強化方案

1. 距離計算昇華：從「個別規則扣分」升級為「全系統加權樹編輯距離 (W-STED)」

將組態狀態空間抽象為階層樹 \(T=(V, E)\)，每一層賦予 Purdue 模型安全權重 \(w_l\)：

\[D(T_0, T_t) = \sum_{e \in \Delta} w(e) \cdot \delta(v_0, v_t)\]

  • 製程不變量層（Process Registers）：\(w_P = 1.0\) (最高危險)
  • 控制邏輯與模式（Logic / Mode）：\(w_L = 0.9\)
  • 通訊身分驗證（Protocols）：\(w_C = 0.8\)
  • 網關存取管理（Management）：\(w_M = 0.5\)
  • 設備環境元數據（Environment）：\(w_E = 0.2\)

定義 歸一化飄移指數 (Normalized Drift Index, \(NDI \in [0, 1]\))，使系統飄移程度具備完全可量化、可比較的數學閉環。

2. 加入「物理互鎖不變量 (Physical Invariant Constraints)」判定

對齊頂會 USENIX Security 2025 (GeCos) 理論，在規則庫加入關聯式物理不變量：

\[\text{Invariant 1: } \text{lit101\_low\_level} < \text{lit101\_high\_level} < \text{lit101\_overflow}\]

\[\text{Invariant 2: } \text{if pump\_mode == FORCE\_ON} \implies \text{pressure} \le \text{cutoff\_psi}\]

只要攻擊者修改的數值違反物理互鎖，即便在合法數值區間內，依然直接判定為 CRITICAL 製程威脅。

3. OpenWrt 網關「雙軌審計 (Dual-Track Auditing)」

OpenWrt 網關同時負責維護工控防火牆與 Modbus 轉發。otdrift 在 OpenWrt 上同時審計兩條軌道：

  1. 下向軌道 (Southbound)：定時透過 Modbus TCP (FC 03) 審計 PLC 暫存器。
  2. 本機軌道 (Local Track)：即時審計 OpenWrt 本機 UCI 組態檔（/etc/config/firewall），防止攻擊者竄改網關防火牆白名單！
