🏛️ 二、 工控資料之「五層結構化模型」與數學形式化定義

指導教授核心指示：「不要將資料視為黑盒子或隨意鍵值對，必須做階層式結構化分析，並給出數學形式化定義」。

1. 五層結構化模型 (ISA-95 / Purdue Model Alignment)

Purdue 分層 代表欄位路徑 資料型態 物理 / 工程意義 資安與製程威脅意涵
第 0/1 層【實體製程層】 process_registers.pump_cutoff_pressure_psi Integer 水泵緊急停機壓力閥值 竄改會導致水錘效應、管線超壓爆裂或儲槽溢流（如 2024 德州水廠攻擊）。
第 1 層【控制邏輯層】 safety_and_integrity.program_checksum String (SHA-256) 梯形圖 (Ladder/ST) 程式指紋 雜湊不符代表控制邏輯已被植入後門或遭 Stuxnet 模式篡改。
第 1 層【控制邏輯層】 safety_and_integrity.plc_mode Enum (RUN/STOP) PLC CPU 實體掃描開關 切換為 STOP 會立即中斷微秒級掃描週期 (Scan Cycle)，全廠停擺。
第 1/2 層【現場通訊層】 protocols.modbus_tcp.auth_required Boolean Modbus 通訊是否強制身分驗證 關閉代表任何內網節點皆可用 Function Code 05/06/16 竄改暫存器。
第 1/2 層【現場通訊層】 protocols.modbus_tcp.allowed_master_ips List[String] 授權發送指令之 SCADA/HMI IP 白名單擴大代表攻擊者可進行橫向移動與未授權指令注入 (T0855)。
第 2/3 層【運維管理層】 management.allow_remote_programming Boolean 是否允許遠端置換 PLC 邏輯 開啟代表攻擊者可直接透過網路覆寫控制器韌體或程式 (T0843)。
基礎層【資產環境層】 device_info.firmware_version String 控制器韌體版本代碼 韌體降級通常代表攻擊者企圖重新引入已修補之 1-day 漏洞 (T0857)。

2. 數學形式化定義 (Formal Mathematical Formulation)

定義 1（設備狀態空間 $\Omega$）：工控設備狀態 $S \in \Omega$ 定義為一結構化多元組：

\[S = (D, N, P, M, L, R)\]

其中 $D$ 為設備資產向量 (Device Metadata)、$N$ 為網路拓撲 (Network)、$P$ 為通訊協定參數 (Protocols)、$M$ 為管理政策 (Management)、$L$ 為控制邏輯不變量 (Logic)、$R$ 為關鍵製程暫存器 (Process Registers)。

定義 2（黃金基準與飄移算子 $\Delta$）：給定受數位簽章保護的黃金基準 $S_0$ 與即時採集狀態 $S_t$，組態飄移集合 $\Delta(S_0, S_t)$ 定義為所有路徑鍵值或型態相異之元組集合：

\[\Delta(S_0, S_t) = \left\{ (p, v_0, v_t, \tau) \;\middle|\; p \in \text{Paths}(S_0 \cup S_t), \; v_0 \neq v_t \lor \text{Type}(v_0) \neq \text{Type}(v_t) \right\}\]

其中異動型態 $\tau \in \{\text{MODIFIED}, \text{ADDED}, \text{REMOVED}, \text{TYPE\_CHANGED}, \text{LIST\_CHANGED}\}$。

定義 3（嚴重度與威脅映射函數）：安全評估引擎定義兩組映射：

  • 嚴重度評級：\(\Phi: \Delta \rightarrow \{\text{CRITICAL}, \text{HIGH}, \text{MEDIUM}, \text{LOW}, \text{INFO}\}\)
  • 國際戰術對齊：\(\Psi: \Delta \rightarrow \mathcal{M}_{\text{ICS}}\)（對齊 MITRE ATT&CK for ICS 技術知識庫）

🌳 四、 核心演算法剖析：為何採用樹狀語意比對？

痛點回顧：若直接套用傳統 Linux diff 或 Git 逐行比對工控設定檔，將引發致命問題：

  1. 順序無關性假警報：工控白名單中 ["192.168.1.10", "192.168.1.20"] 與 ["192.168.1.20", "192.168.1.10"] 意義完全相同，字串比對會判定整行變更，引發 100% 假警報；otdrift 的 AST 比對開啟 ignore_order=True，正確判定 0 飄移。
  2. 型態突變偽裝 (Type Confusion)：將連接埠 502（Integer）惡意注入為 "502"（String）在純字串比對常被忽略，但弱型別 PLC 韌體解析時將造成記憶體溢位或協定崩潰。otdrift 具備強型別檢驗，獨立歸類為 TYPE_CHANGED。
  3. 語意子樹剪枝 (Subtree Pruning)：若整組 protocols.modbus_tcp 被移除，傳統比對會爆發數十條無意義字串差異；otdrift 立即標記父節點 REMOVED 並計算受影響製程危害度。

💡 八、 今晚專題報告評審教授關鍵答辯話術 (Defensive Q&A)

Q1：你們跟市面上組態管理軟體（例如 Ansible、Tripwire）有何本質差別？

答辯重點：傳統 IT 工具僅做「字串級 Diff」或強制推送期望狀態，在工控環境隨意覆寫會導致產線跳脫與爆管。otdrift 的本質是「OT 語意感知與安全不變量檢驗」：
1. 它知道 pump_cutoff_pressure_psi 從 85 變成 140 不只是純數值改變，而是會導致管線超壓爆裂的 CRITICAL 製程威脅。
2. 它能直接映射 MITRE ATT&CK for ICS（T0839），並動態合成現場安全處置手冊（Playbook）。

Q2：為什麼你們比對是在離線或容器邊界進行，而不直接對 PLC 做主動連續掃描？

答辯重點：這正是我們遵守工控最高原則「零干擾（Zero-Disruption）」的核心設計。PLC 依靠微秒級的固定掃描週期（Scan Cycle）維持即時控制。任何主動滲透掃描封包都會造成 PLC 網路緩衝區溢位或週期延遲，引發非預期跳機。otdrift 透過被動匯流排採集與無感快照，完全不侵入即時控制迴路。

Q3：教授提到「階層結構與距離計算」，你們是如何實作的？

答辯重點：我們將工控組態抽象為樹狀結構 \(T=(V, E)\)，每一層對應 Purdue 5-Layer 模型（製程層、邏輯層、通訊層、管理層）。距離計算結合了：
1. 樹編輯距離（Tree Edit Distance）：衡量節點的新增、刪除與型態變更。
2. 風險權重矩陣（Severity Weight Matrix）：賦予製程安全閥值與通訊認證極高權重（0.9~1.0），使資安風險得以量化為 0~100 的整體風險分值。
